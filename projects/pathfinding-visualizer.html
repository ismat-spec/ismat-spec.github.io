Pathfinding Visualiser

Four classic search algorithms — A*, Dijkstra, Breadth-First Search and Greedy Best-First — animated live on an interactive grid. Draw walls, add slow terrain, generate a maze, and watch each algorithm think. Built from scratch in vanilla JavaScript, no libraries.

1Project Scope & Problem

Pathfinding is everywhere — game characters navigating a map, delivery routing, robot vacuum cleaners, network packets. The algorithms behind it are a core part of computer science, but taught on paper they stay abstract: it is hard to feel why A* is clever or where Greedy Best-First goes wrong just by reading pseudocode.

My goal was to build the explanation I wished I'd had: an interactive playground where the search is animated cell by cell, where you can build your own obstacle course, and where the numbers — cells visited, path cost, compute time — let you compare algorithms like an engineer rather than take the textbook's word for it. As a browser app with no install, it also had to be something anyone can try in one click.

2My Role & Solution

Solo build, everything from scratch: the grid engine, the four algorithms, the animation system and the UI. I deliberately used no frameworks or libraries — the whole app is one hand-written HTML/CSS/JavaScript file — because the point was to demonstrate the fundamentals, including the data structures (the priority queue is a hand-rolled binary min-heap).

The grid supports walls (impassable) and "sand" (passable but costing 5 instead of 1), which is what makes the algorithm comparison interesting: Dijkstra and A* route around expensive terrain, while BFS — which counts steps, not cost — ploughs straight through it and proudly reports a worse path. A recursive-division maze generator provides an instant challenge, and start and target are draggable.

3Work Process

The design decision I'm most pleased with is the strict separation between search and animation. Each algorithm runs to completion first, pure and synchronous, returning the visit order and parent pointers without touching the page. The animation layer then replays that record at whatever speed the user chose. This kept the algorithms textbook-clean, made the compute-time stat honest (it measures the search, not the drawing), and meant one animation system serves all four algorithms.

All four searches share one engine with a swappable priority function — Dijkstra orders its frontier by cost-so-far, A* by cost-plus-heuristic (Manhattan distance), Greedy by heuristic alone, and BFS by arrival order. Seeing them as the same loop with different priorities was the real lesson of the project. The finishing work was interaction detail: pointer events so wall-drawing works with mouse and touch, a run token so restarting mid-animation cancels cleanly, and a colour scheme checked for colour-blind separation between the visited, frontier and path layers.

4Outcome & Results

The finished app does exactly what I set out to make: a one-click, install-free playground where the differences between the algorithms stop being theory. Race them on the same maze and the stats tell the story — A* reaches the target visiting roughly 15% fewer cells than BFS; Greedy finishes fastest but returns visibly longer paths; BFS ignores sand and pays for it in path cost. Searches on the 1,012-cell grid complete in tens of milliseconds, so the animation speed is purely a teaching control.

It also became the most demonstrable thing in my portfolio: it runs live inside this site, on any device, with nothing to install. Try it yourself — generate a maze, run A*, then switch to Greedy Best-First and watch it get greedy.
